An abstract class is called a blueprint because it only describes what every child class must have, and it is not a finished object itself. Like a house plan, you can’t live in it, but you can build real houses from it, so a generic “Vehicle” shouldn’t exist on its own. When we use the @abstractmethod decorator, we force the child classes to implement their own version of that specific method. If you try to create an object directly from an abstract class, such as my_car = Vehicle(), Python raises a TypeError and refuses to create it. This protects the program from having a generic object whose method has no real behavior.
